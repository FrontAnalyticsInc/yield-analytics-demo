# Power BI

The semantic model is kept as code in `powerbi/` (Power BI Project, TMDL format).
It is generated by `powerbi/generate_model.py`: edit the spec there, re-run it, and commit.

## What's in the model

- **Tables:** `dim_step`, `dim_defect`, `dim_operator`, `dim_equipment`, `dim_lot`, `fact_unit`, `fact_step_event`, `fact_inspection`, plus a calculated `Date` table.
- **Relationships:** a star around `fact_step_event`. `fact_unit` joins to `Date` on completion date through an inactive relationship; the unit measures activate it with `USERELATIONSHIP`.
- **Measures:**
  - Unit yield: `First Pass Yield`, `Final Yield`, `Units Completed/Shipped/Scrapped`, `WIP`, `Avg Cycle Days`
  - Step yield: `Step FPY`, `Rolled Throughput Yield` (the product of step FPYs over the steps in context), `First Attempt Fail Rate`, `Rework Events`, `Scrap Events`
  - SPC: `Measurement Mean`, `Measurement StdDev`, `Cpk` (use it with one `dim_step` selected)
  - Vision: `AI Agreement`, `AI Recall`, `Defects Missed by AI`
- **Links:** `fact_inspection[image_url]` is categorised as *Image URL*, and `unit_url` columns as *Web URL*. They open the deep-dive app.

## Data source

The expression `Load Parquet` reads `<BaseUrl>/<table>.parquet?key=<AccessKey>` with
`Web.Contents` and `Parquet.Document`. The base URL is fixed and each table is a
`RelativePath`, so Power BI Service treats it as a single static web source and
**refreshes without a gateway**.

| Parameter | Value |
|---|---|
| `BaseUrl` | `https://yield.frontanalytics.com/exports` |
| `AccessKey` | the `EXPORT_KEY` from walden's `.env` |

### Switching to Azure Blob / ADLS

Once an Azure subscription exists:

```bash
az group create -n rg-yield-demo -l eastus2
az deployment group create -g rg-yield-demo -f infra/main.bicep
az storage account show-connection-string -g rg-yield-demo -n <storageAccount> -o tsv
# put that in walden's .env as AZURE_STORAGE_CONNECTION_STRING, then: docker compose up -d exporter
```

Then replace the body of `Load Parquet` with:

```m
(name as text) as table =>
let
    Files = AzureStorage.DataLake("https://<storageAccount>.dfs.core.windows.net/yield/parquet"),
    Bin   = Files{[Name = name & ".parquet"]}[Content]
in
    Parquet.Document(Bin)
```

In Power BI Service, set the data source credential to *Account key* or *OAuth2 (Organizational account)*.

## One-time setup (≈ 30 minutes, Windows)

1. Install **Power BI Desktop** (Microsoft Store) and turn on *File → Options → Preview features → Power BI Project (.pbip) save option* and *Store semantic model using TMDL format*.
2. Open `powerbi/YieldAnalytics.pbip`. When prompted, enter the `AccessKey` parameter (*Transform data → Edit parameters*), then **Refresh**.
3. Build the report pages below. The report skeleton already contains the five empty pages.
4. **File → Save** writes the report back into `powerbi/YieldAnalytics.Report`. Commit it.
5. **Publish** to a workspace (e.g. *Yield Demo*). This needs a Power BI Pro, PPU or trial license.
6. In the Service: *Semantic model → Settings*:
   - *Data source credentials*: `Web`, **Anonymous**, privacy level *Organizational*. The key travels in the query string.
   - *Scheduled refresh*: hourly, or the 8/day Pro allows (e.g. every 3 hours in working hours).

## Suggested report pages

| Page | Visuals |
|---|---|
| **Overview** | Cards: First Pass Yield, Rolled Throughput Yield, Final Yield, Units Completed, WIP, Avg Cycle Days. Line: FPY and Final Yield by `Date[Month]`. Slicers: `Date`, `fact_unit[model]`. |
| **Step Yield** | Bar: `Step FPY` by `dim_step[name]`, sorted ascending, top 10. Matrix: `dim_step[area]` → `dim_step[name]` with First Attempts, First Attempt Fail Rate, Rework Events, Scrap Events. |
| **Root Cause** | Bar: `First Attempt Fail Rate` by `fact_step_event[operator_id]` / `dim_lot[tissue_lot]` / `fact_step_event[equipment_id]` (use a field parameter to switch). Slicer on `dim_step[area]`. Pareto: Defect Events by `dim_defect[description]`. |
| **SPC** | Slicer: `dim_step[name]` filtered to `step_type = measurement` (single select). Scatter or line: `fact_step_event[value]` by `ended_at`, legend `equipment_id`. Constant lines at `dim_step[lsl]`/`usl`. Card: `Cpk`. Table: Cpk by equipment. |
| **Image Inspections** | Cards: Images, AI Agreement, AI Recall. Matrix: rows `true_class`, columns `ai_class`, value Images (confusion matrix). Table with `image_url` (shows thumbnails), `serial`, `true_class`, `ai_class`, plus `unit_url` as a link, filtered to defects. |

## Deploying from git (optional, later)

For a team of 20+, connect the workspace to this repo with **Fabric Git integration**
(needs a Fabric/PPU-capable workspace), or use **deployment pipelines** (dev → test → prod).
A service principal can publish from GitHub Actions if a tenant admin enables
*"Service principals can use Fabric APIs"* and adds the app registration to the workspace.
